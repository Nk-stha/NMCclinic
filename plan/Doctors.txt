  Do not index every filter state unless it has unique, crawlable content. For SEO, a doctor profile should include unique bio, specialty, qualifications,
  schedule, clinic location, profile image, and appointment CTA.

  Structured data:

  - Listing page: MedicalBusiness or clinic-level structured data, plus BreadcrumbList.
  - Doctor detail page: physician/person-style structured data where valid, connected to clinic organization.
  - Avoid schema claims that are not source-backed.

  Heading hierarchy:

  - One H1: current hero headline.
  - H2: doctor grid/CTA section headings if added.
  - H3: doctor names inside cards are acceptable.
  - Doctor detail pages should have H1 as doctor name.

  Publish rule: a doctor should not be publicly visible unless name, primary specialty, qualification, registration number, schedule/availability, and photo
  alt text are complete.

  Media Management
  Doctor photos should be stored in media_assets, not embedded in page content. Store width, height, MIME type, file size, alt text, title, caption, and focal
  point. Generate WebP/AVIF responsive variants. Lazy-load doctor grid photos. Do not lazy-load the hero/LCP image if it becomes a foreground image.

  Alt text pattern: Dr. Full Name, Specialty at NMC Clinic Butwal.

  Performance
  Best fit: SSG/ISR for listing and doctor profiles if using Next.js. Doctors and schedules change occasionally, not every request.

  Recommended query: fetch page SEO + visible specialties + published visible doctors + primary specialty + qualifications + schedule summary + photo in one
  optimized endpoint. Cache public payload by locale. Use CDN caching for doctor images. Keep filter client-side only for already-loaded data unless the
  doctor count grows large.

  Security
  Sanitize doctor bios, qualifications, schedule labels, CTA URLs, image metadata, and SEO fields. CMS uploads need MIME/extension/size/dimension validation.
  Restrict doctor publish permission because this is medical credibility content. Keep audit logs for doctor profile and schedule changes.

  Current Risks
  The current page is not production-ready as a doctor listing because it renders placeholder names, qualifications, registration numbers, and photos. There
  is also no page <title>, meta description, canonical, Open Graph, or structured data. The View Profile links currently point back to the homepage doctors
  section, not individual doctor profiles.

  Best Practice
  Model doctors as first-class entities. Do not bury them in a generic JSON page section. Use page_sections for the Doctors page layout, specialties for
  filtering, and doctors for real medical staff data. This keeps the listing page, homepage teasers, appointment form, and future doctor profile pages
  consistent.
