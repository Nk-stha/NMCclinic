  Static Fields
  Keep static unless redesigning: layout direction logic, grid/flex structure, color tokens, spacing scale, typography, responsive breakpoint, hover styling,
  section component types, icon rendering mechanism. Do not store raw CSS/HTML in the CMS.

  Recommended Database Design

  appointment service options, sitemap URLs, and internal links.

  Google guidance used: create useful crawlable pages, use descriptive titles/descriptions, add structured data when it helps search engines understand
  content, keep metadata consistent on mobile, and optimize Core Web Vitals for real user experience.

  Media Plan
  Current specialty media are placeholders like consultation room photo, not real images. Each specialty should have a real image with:

  - Alt text: specific, not keyword-stuffed.
  - Width/height stored to prevent layout shift.
  - WebP/AVIF generated variants.
  - Responsive sizes.
  - Lazy loading for specialty detail images below the hero.
  - Hero background should be optimized carefully because it may affect LCP.

  Performance
  Best fit: SSG or ISR if moving to Next.js. This page is mostly editorial and changes rarely.

  Recommended public query shape: fetch published page, SEO, visible sections, visible specialties, specialty points, and media in one optimized call. Cache
  by slug + locale. Use CDN caching for images. Keep payload structured and avoid shipping unpublished/version data to public pages.

  Security
  Sanitize specialty descriptions, CTA labels, CTA URLs, image metadata, and any rich text. Restrict icons to approved keys; do not allow raw SVG/HTML from
  CMS users. Validate uploads by MIME, extension, dimensions, and size. Require CMS permissions for specialty create/edit/publish/delete.

  Potential Issues
  Current source has no <title> or meta description. Specialty images are placeholders. Social/legal footer links still use href="#". Contact numbers are
  placeholders. The current icons are raw SVG path strings; in a CMS version, use trusted icon keys instead of storing raw SVG.

  Best Practice
  Use a dedicated specialties table because this content is reusable across pages and workflows. Avoid making every visual section a separate custom table.
  Use reusable page_sections for page composition, and use specialties for actual medical service entities.
